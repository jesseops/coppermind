## Goal
Implement JSON API endpoints and OPDS catalog for e-reader integration.

## JSON API (`/api/v1/`)
- Handler: `internal/web/handlers/api.go`
- Auth: same session cookie or HTTP Basic Auth for API clients
- Content-Type: application/json

### Endpoints
- `GET /api/v1/works` — paginated, filterable (same params as HTML)
- `GET /api/v1/works/:id` — work detail with editions
- `GET /api/v1/editions/:id` — edition detail
- `GET /api/v1/me/reading` — current reading states
- `POST /api/v1/me/reading/:edition_id` — update reading progress
- `GET /api/v1/authors` — list authors
- `GET /api/v1/series` — list series

## OPDS Catalog (`/api/v1/opds/`)
- Handler: `internal/web/handlers/opds.go` or `internal/opds/opds.go`
- Implementation: `internal/opds/` — generate Atom/OPDS XML feeds

### Feeds (from DESIGN_V2.md §6)
- Root catalog (`/api/v1/opds`) — navigation feed with links to sub-feeds
- New acquisitions (`/api/v1/opds/new`) — recent works sorted by date
- Authors (`/api/v1/opds/authors`) — navigation feed, then per-author acquisition feed
- Series (`/api/v1/opds/series`) — navigation feed, then per-series acquisition feed
- Search (`/api/v1/opds/search`) — OpenSearch descriptor + results feed

### OPDS entry format
- Each work entry includes: title, author, description, cover image link, download links per edition (with format/size)
- Acquisition links use proper OPDS relation types
- Content types: application/atom+xml;profile=opds-catalog

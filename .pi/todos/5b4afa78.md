## Goal
Define all core domain structs in `internal/domain/`. These are plain Go types with no database dependencies — they represent the business domain.

## Files & types
- `work.go`: `Work` struct (ID, LibraryID, Title, SortTitle, Description, SeriesID, SeriesIndex, Language, FirstPublished, CoverPath, CreatedAt, UpdatedAt)
- `edition.go`: `Edition` struct (ID, WorkID, EditionType, Format, ISBN, Publisher, PublishedYear, Narrator, DurationSeconds, FilePath, FileHash, FileSize, CoverPath, Notes, Status, CreatedAt, UpdatedAt)
- `author.go`: `Author` struct (ID, Name, SortName, CreatedAt), `WorkAuthor` struct (WorkID, AuthorID, Role)
- `series.go`: `Series` struct (ID, Name, Description, CreatedAt)
- `user.go`: `User` struct (ID, Username, DisplayName, PasswordHash, Role, CreatedAt, UpdatedAt), roles as constants
- `reading_state.go`: `ReadingState` struct per design §3
- `shelf.go`: `Shelf`, `ShelfWork` structs
- `library.go`: `Library` struct
- `track.go`: `Track` struct
- `tag.go`: `WorkTag` struct

## Notes
- Use value types (not sql.Null*) — the store layer handles DB nullability
- Include helper methods: `Work.HasCover()`, `Edition.IsEbook()`, `Edition.IsAudiobook()`, `User.IsAdmin()`, etc.
- SortTitle generation: strip leading articles ("the", "a", "an"), lowercase
- SortName generation: "Brandon Sanderson" → "sanderson, brandon"

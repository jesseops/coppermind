## Problem
Reading state (`reading_states` table) exists and has a "Currently Reading" page,
but it is never automatically updated. Users must manually trigger state changes,
and there's no clear UX for doing so.

## Current State
- `reading_states` table tracks: user_id, edition_id, status, progress,
  chapter_index, scroll_position, track_index, position_seconds, started_at, finished_at
- `handleSaveReadingState` endpoint exists (`POST /api/v1/me/reading/{id}`)
  but is only called by... nothing in the current templates
- "Currently Reading" page (`/me/reading`) shows states with status="reading"
- No way to mark a book as "reading", "finished", or "want to read" from the UI

## Proposal

### Automatic State Updates
1. **Opening the reader/player** → auto-set status to "reading" + started_at if not already
2. **Reader progress** → Periodically save chapter_index + scroll position (every 30s or on chapter change)
3. **Player progress** → Save track_index + position_seconds on pause/track change
4. **Reaching end** → Prompt "Mark as finished?" or auto-mark

### Manual State Controls
Add a reading status button/dropdown on:
- Work detail page (next to Read/Listen buttons)
- Card action menu in catalogue

States: `want_to_read` → `reading` → `finished` (+ `abandoned`)

### UI Implications
- "Currently Reading" becomes more useful with actual data
- Could add "Want to Read" and "Finished" tabs/filters
- Reading history timeline (ordered by last activity)
- Progress bars on work cards in "Reading" view (already partially implemented)

### Backend Changes
- Reader template: add JS to POST progress on chapter navigation and periodic timer
- Player template: add JS to POST progress on track change / periodic timer
- New handler or extend existing: `POST /api/v1/me/reading/{edition_id}/status`
  with body `{"status": "reading|finished|want_to_read|abandoned"}`
- Work detail: show current reading state if one exists
- Catalogue: optionally filter by reading status ("Show: Want to Read")

## Priority
Medium — the infrastructure exists, it just needs wiring up. The UX impact is
significant for active readers who want to track their progress.
